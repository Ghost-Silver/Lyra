# 安全边界与威胁模型（Lyra arm_sim）

> 适用范围：`app/main.cpp`（`arm_sim` 服务）+ `lib/arm/control/`（HTTP/WS/串口/安全监控）。
> 本文对应提交 `arena/01a0d869-lyra`（PR #1）。**本服务是实验室工具，不是生产级机器人控制器。**

## 1. 一句话结论

**默认无认证、无 TLS、监听所有网卡** —— 只可部署在受信内网（或 `127.0.0.1` + SSH 端口转发）。
**绝不可直接暴露到公网或不可信网络**：能连上 8080 端口的人可以下发关节/末端目标、清除急停、
回放示教轨迹。若必须跨网段使用，请在反向代理层补齐认证 + TLS + 网络隔离（见 §5）。

## 2. 威胁模型

| 角色 | 能力假设 | 关注点 |
| --- | --- | --- |
| 受信操作员（本机/实验室内网） | 可访问页面与 WS | 误操作（越限目标、错误轨迹）；急停可用性 |
| 同网段不可信主机 | 可向 8080 发起 TCP/HTTP/WS | 未授权控制、DoS（连接/内存/CPU 耗尽）、信息泄露 |
| 恶意网页（浏览器侧） | 可诱导用户浏览器发起跨站 WS | 无认证下的"跨站驱动机械臂"（默认放行任意 Origin） |
| 物理/电气层 | 真机接入后 | 软件越限指令到达执行器的后果（本仓只有仿真 + 预留驱动） |

**不在本仓范围内的**：操作系统/内核漏洞、硬件故障、供电与机械失效、CTorch 上游供应链
完整性（仅固定 SHA + 补丁记录）。

## 3. 未实现/不提供的防护与后果（如实清单）

| 缺什么 | 后果 | 当前缓解 |
| --- | --- | --- |
| **认证/授权**（无 token/密码/会话） | 任何可连通者均可下发全部指令，包括 `estop{on:false}`（解除急停）与 `reset` | 无。仅靠网络边界 |
| **TLS/WSS** | 明文 JSON：可嗅探状态与指令、可中间人篡改 | 无。靠内网或反向代理 |
| **Origin 强制**（默认放行所有 Origin） | 用户浏览器访问恶意页面时，页面可跨站直连 WS 下发指令（无 Cookie 即无 CSRF 面，但 WS 本身不校验来源） | `--allow-origin URL`（可重复）设白名单；⚠️ 须自行启用，**默认关闭** |
| **速率限制/配额**（除连接数 16、队列 256 KiB、消息 1 MiB 外） | 已连接客户端可高频指令（如 1 kHz `joint_vel`）使仿真 CPU 升高、界面滞后；不影响已建立的 50 Hz 广播与安全层，但属可用性风险 | 单连接发送队列有界（慢客户端被丢弃）；无指令频率上限 |
| **审计日志/操作追溯** | 无法事后还原"谁在何时下发什么" | 服务端仅 stdout 摘要；无持久化审计 |
| **权限分级/工况互锁**（如"仅示教模式可回放"） | 任意客户端可切换模式、清示教、覆盖急停后的状态 | 急停可锁存（`estop{on:true}` 需显式解除） |
| **真机安全回路**（硬件急停、看门狗、力矩限幅） | 接入真实执行器后，软件层失效即无最后防线 | 串口驱动仅留桩（`serial_driver.hpp`），本仓未接真机 |
| **输入模糊测试/渗透测试** | 未知的解析边界问题 | 已有解析器限额（§4）+ 单测，但无 fuzz 与第三方渗透 |

## 4. 已实现的防护（含开关与默认值）

### 4.1 网络与协议（`lib/arm/control/ws_server.hpp`）

| 防护 | 默认值/开关 | 说明 |
| --- | --- | --- |
| 客户端帧强制掩码 | 强制 | 违反 → 协议错误关闭（RFC6455） |
| 控制帧 ≤125 字节、禁分片；孤立 Continuation 拒收 | 强制 | 帧层回归在 `tests/test_json_ws.cpp` |
| 握手三件套校验（`Connection: Upgrade` / `Sec-WebSocket-Version: 13` / 合法 `Sec-WebSocket-Key`） | 强制 | 缺失/非法 → 拒绝升级 |
| 单帧/消息上限 | 1 MiB | 超出 → 协议错误 |
| 读缓冲上限 | 2 MiB | 超出 → 丢弃连接 |
| 每连接发送队列上限 | 256 KiB | **严格非阻塞**：慢客户端被丢弃，绝不阻塞控制循环 |
| 连接数上限 | 16 | 第 17 个连接 → **HTTP 503 `busy`**（前端可感知），计数见 `/api/health.rejected_clients` |
| HTTP 请求头上限 | 16 KiB | 超出 → 立即丢弃并计数（`header_rejects`） |
| slowloris 超时 | 5 s 无活动 | 半开/慢速连接回收（实测 RST→回收 13.9 ms） |
| 静态文件路径校验 | 强制 | `realpath` 前缀 + `O_NOFOLLOW`：`../` 与 symlink 逃逸 → 403 |
| 静态文件体积上限 | 192 KiB（超出 413）+ 8 MiB 内存缓存 | 避免大文件读取阻塞实时控制循环（2 MiB 直读 ≈ 6.4 ms = 3 个控制周期） |
| Origin 白名单 | **可选，默认放行所有** | `--allow-origin URL`（可重复；`*` 为通配条目）；无 Origin 的非浏览器客户端始终放行 |
| 示教点上限 | **4096 点**（≈196 KB） | 未鉴权 WS 可反复 `teach_add`；超限回 `error{teach_full}` 并计数（`/api/health.teach_points` 观测水位） |
| 串口待发队列上限 | **16 KiB**（丢最旧 + 计数） | 真机路径：部分写续传 / `EAGAIN` 重试 / 硬错误离线；离线后不再入队（防无界增长），计数见 `/api/health.serial_*` |
| 串口读缓冲上限 | **4 KiB** | 半截帧/垃圾流清空并计数（`serial_rx_overflow`） |

### 4.2 实时安全层（`lib/arm/control/safety_monitor.hpp`，独立于规划/IK）

| 防护 | 默认 | 说明 |
| --- | --- | --- |
| 下发前位置硬 clamp + 计数 | **开启** | 越限的关节目标被截断到 `qmin/qmax`，计数进 `/api/health` 与状态 JSON `safety.pos` |
| 积分后位置投影（状态侧审计） | 开启 | 仿真状态越限 → 投影回边界并计数（`safety.pos_state`） |
| 速度上限 | 开启 | `|qd| ≤ vmax`（`safety.vel`） |
| 加速度上限（差分） | 开启 | 相邻拍差分超 `amax` 容差 → 计数（`safety.acc`） |
| 单拍位移上限（跃变回滚） | 开启 | 位置目标跳变 > `stepFactor=1.5`×vmax·dt → 回滚并清零速度（`safety.step`，对应历史 P0-1 类故障的兜底） |
| 越限急停（锁存） | **默认关闭** | `--safemon-estop` 开启；触发时强制速度 0 并锁存（`safety.estop`） |
| 关闭整个监控层 | 默认启用 | `--no-safemon` 关闭（用于对照实验；**真机场景不建议**） |
| 轨迹时间基准校验 | 开启 | 空/非严格单调/末值≤0 的轨迹**拒播并报错**（不静默跳到终点） |

### 4.3 其他

- `lib/arm/control/json.hpp`：解析深度上限 200、严格 JSON 数字语法、越界安全取值（单测覆盖）。
- 伺服层：软件限位与急停锁存在 `ArmSim` 内层，任何上层路径（PTP/直线/圆弧/抓取/拖拽/速度模式）都无法绕过（`tests/test_safety.cpp` 覆盖）。
- 依赖：CTorch/C3 固定 SHA（`third_party/PATCHES.md`），补丁全部记录且可回归验证。

## 5. 部署建议（运维可直接照抄）

1. **绑定与网络**
   - 优先 `127.0.0.1`（配合 SSH 端口转发 `ssh -L 8080:127.0.0.1:8080 lab-host`）。
   - 内网共享必须时：用防火墙只放行实验网段，禁止 0.0.0.0 直连公网（服务默认监听所有网卡）。
2. **认证与加密**：在反向代理（nginx/Caddy）加 HTTP Basic/OIDC + TLS，并**只转发 `/_ws` 与静态路径**；WS 升级请求同样过认证。
3. **Origin 收紧**：`--allow-origin https://<你的前端域>`（可重复）。注意它不是认证，只是减少浏览器跨站面。
4. **保持默认开启的安全层**：不要用 `--no-safemon`；建议加 `--safemon-estop` 并让上层监控 `/api/health` 的 `safety.*` 计数与 `rejected_clients`。
5. **资源**：单实例面向少量操作员（连接上限 16）。多用户请部署多实例 + 前置网关，不要调大限额。
6. **真机接入前**：必须实现独立的硬件急停回路与看门狗；本服务只可作为"上层指令源"，不得作为唯一安全链路。
7. **暴露面检查清单**：① 8080 是否只对受信网段开放？② 是否有 TLS？③ `--allow-origin` 是否设置？④ `/api/health` 是否被外部可读（会泄露客户端数与拒绝计数，风险低但非必要）？

## 6. 已披露但接受的风险（本仓定位决定）

- 无认证/无 TLS：为"实验室数字孪生 + 教学演示"场景换取零依赖部署，**已在 README 与本文显式披露**。
- 无指令速率限制：仿真场景下最坏后果是界面迟滞；真机场景必须由下游（硬件/网关）限速。
- Origin 默认放行：为兼容浏览器预览代理与本地开发；生产部署必须显式收紧。
